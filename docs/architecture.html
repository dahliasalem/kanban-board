System

Client, Firestore, and Cloud Functions

The client reads and writes boards, columns, and cards directly against Firestore for real-time speed. Every card write also appends a version, which triggers a function that formats it into the activity feed; a separate trigger on invites sends email through an external provider. A third, non-triggered API route proxies Unsplash searches so the API key never reaches the browser.

Data model

Collections and what they store

Current board state is plain CRUD — cards hold live fields updated in place. History is derived: every edit is logged as a version, and the activity feed is a materialized projection of that log, not a separately maintained table.

Flow · card move

Drag a card, feed updates live

The position write is optimistic-concurrency, not last-write-wins: if the card changed since it was read, Firestore aborts the transaction and the SDK retries it automatically against fresh data. 

sequenceDiagram
  actor U as User
  participant C as Client
  participant F as Firestore
  participant Fn as Cloud Function
  participant L as Other clients

  U->>C: Drag card to new column
  C->>C: Optimistic local update
  C->>F: Transaction — update column + fractional position, append version
  alt No conflicting write
    F-->>C: Commit succeeds
  else Card changed since read
    F-->>C: Abort — SDK retries automatically
    C->>F: Re-run transaction on fresh data
    F-->>C: Commit succeeds
  end
  F->>Fn: onCreate(version) trigger
  Fn->>Fn: Diff into a readable line
  Fn->>F: Write entry to activityFeed
  F-->>C: onSnapshot pushes board + feed update
  F-->>L: onSnapshot pushes same update
  C-->>U: Board and feed update instantly
Flow · invite

Inviting a collaborator by email

Every invite goes through email regardless of account status — new users get a signup link, existing users get a lighter "shared with you" email that points back into the app. 

sequenceDiagram
  actor U as Board owner
  participant C as Client
  participant F as Firestore
  participant Fn as Cloud Function
  participant E as Email API
  actor I as Invitee

  U->>C: Enter invitee's email, send invite
  C->>F: Create invite doc — status: pending
  F->>Fn: onCreate(invite) trigger
  Fn->>F: Look up email against users
  alt Existing user
    Fn->>E: Send "shared with you" email
  else New user
    Fn->>E: Send "join the board" signup email
  end
  E-->>I: Email delivered
  I->>C: Click join link
  C->>F: Transaction — validate invite, add as board member
  F-->>C: Real-time board access granted
